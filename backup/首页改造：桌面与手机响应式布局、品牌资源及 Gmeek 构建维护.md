把默认 Gmeek 首页改成可以长期维护的个人博客：首页采用“夕阳封面＋简约书架”的方向，桌面与手机共用内容、分别排版。按钮、导航和书名使用真实 HTML；图片只承担画面，不把交互烘焙进图片。

本 Issue 是实施方案与任务清单。除仓库调查外，以下开发及验收均未完成；本次改写不代表首页已上线。

## 页面布局

断点是首版实施建议，按实际内容验证后微调；不按设备型号或 User-Agent 分站。

| 区域 | 桌面 ≥1024px | 平板 768–1023px | 手机 <768px |
| --- | --- | --- | --- |
| 顶部导航 | 站名＋文章入口＋搜索＋主题；内容最大宽度约1200px | 缩短间距，必要时换行 | 保留站名、搜索及必要入口；触控区域至少44×44px |
| 夕阳封面 | 横版约16:9；人物与文字留独立安全区 | 根据容器裁切并调整焦点 | 使用单人竖版素材，约3:4展示；不直接缩小桌面整图，不强制占满一屏 |
| 按钮 | HTML“进入书架”锚点，可直接滚至正文 | 同左 | 放在正常文档流中，宽度适合拇指操作，不被浏览器工具栏遮住 |
| 简约书架 | 左侧人物/简介约240–280px，右侧书架/文章区；文章2–3列 | 简介移上方，文章2列 | 人物缩成小插图，文章单列；标题允许换行，标签放下一行 |
| 滚动 | 使用页面原生纵向滚动，右侧滚动条随浏览器显示 | 同左 | 原生触屏滚动；不增加嵌套滚动区，也不画不能操作的假滚动条 |

书架每个条目必须对应真实内容链接；没有内容时显示空状态，不编造书名、文章或点击入口。搜索沿用 /tag.html，文章及 RSS 保持可用。移动端不能只靠隐藏标题与日期实现适配。

## 文件级实施清单

| 文件/目录 | 动作与目的 |
| --- | --- |
| `config.json` | 设置真实 title、subTitle、displayTitle、avatarUrl、faviconUrl、ogImage；保持 CN；把 GMEEK_VERSION 从 last 固定到实施时验证过的版本。站名、简介和最终素材待定稿，不把建议文案当成已确认决定 |
| `templates/plist.html`（新增） | 从固定版本上游模板建立本地覆盖；输出封面、真实按钮、书架和文章列表；保留分页、搜索、主题逻辑；无文章时输出明确空状态 |
| `templates/base.html`（按需新增） | 若调整全站结构，基于同一版本覆盖；首页宽度使用专用页面类，文章阅读列保持约720–800px，避免把所有页面一起拉宽 |
| `assets/css/home.css`（新增） | 响应式网格、断点、封面焦点、书架、深浅色和焦点样式；覆盖列表 min-width 为0，设置子项 min-width:0；允许标签/标题换行；禁止用 overflow-x:hidden 掩盖内容溢出 |
| `assets/js/home.js`（新增，可选） | 只处理菜单/动画渐进增强；文章和主要导航不依赖 JS 才出现；处理播放失败和减少动态效果偏好 |
| `assets/images/`（新增） | 存放 avatar.webp、favicon.svg/png、hero-desktop.webp、hero-mobile.webp、og-cover.jpg、人物透明素材；文件名为计划命名，尚未接入最终图片 |
| `assets/video/`（第二阶段） | 可选短循环 MP4/WebM；先交付静态图。桌面按需加载，手机默认静态，播放失败仍保留封面及按钮 |
| `.github/workflows/Gmeek.yml` | 明确覆盖上游模板；生成结束后将源 assets 复制到 /opt/Gmeek/docs/assets，再复制回工作区并打包；为配置/模板/assets 的变更增加有路径过滤的 push 构建，避免生成输出触发循环 |
| `blogBase.json`、`docs/*`、`backup/*` | 作为构建输出重新生成，不作为主要修改入口。核对 P1、文章列表、RSS、标签、旧路径是否同步清理 |
| `README.md` | 当前由生成器更新统计；不能仅手改后期待永久保留。新增维护说明可放 `MAINTENANCE.md`，如需 README 展示说明则在生成后追加受控内容 |

样式接入使用自定义 plist 模板直接引入 /assets/css/home.css，或使用已验证的 indexStyle 注入完整 link 标签，二选一避免重复。indexScript 同理。不要假定向配置加入任意新字段就能自动生成组件。

上游源码目前使用 templates/plist.html 渲染首页，并在全量构建中重建输出目录；因此素材源文件放在 assets，生成后再复制进 docs/assets。实施时必须按固定版本再次核实，不能只往 docs 放文件。

## 资源预算（目标，不是现有测量）

- 手机封面建议 ≤300KB，桌面封面 ≤500KB，头像 ≤50KB；单张交付图上限1MB不等于网页首屏预算。
- 首屏总传输目标 ≤1MB（含字体、样式和脚本，不含按需视频）；优先系统字体。
- 动画建议5–8秒、文件约2–4MB，实测后压缩；不使用大型GIF充当视频。
- 浏览器网络面板确认手机未同时请求桌面图和视频；记录缓存关闭时的实际传输量。
